# LUM6001: tsconfig missing options required by Lumen

**Severity:** warning · **Category:** tooling and config (6xxx)

<!-- end of generated header -->
> The project's `tsconfig.json` lacks an option that type checking `.stsx` files depends on.

**Reported by:** `lumen check`, on the option's key in the tsconfig. A
warning: the check still runs, but some files are typed wrongly or not at all.

## What it means

`lumen check` type-checks `.stsx` files through generated shadow TSX files in `.lumen/shadow`
(spec §4.7). That only works when the tsconfig sets:

- `"jsx": "preserve"` and `"jsxImportSource": "lumen"`, so JSX is typed as Lumen JSX;
- `rootDirs` pairing the sources with their shadows (`["src", ".lumen/shadow/src"]`), so
  `import "./Card.stsx"` resolves to the shadow. The warning also fires when `rootDirs` pairs only
  `src` but a Lumen package the project uses (a linked workspace package) has `.stsx` files: they
  are outside the pair and are not type-checked;
- `include` covering `.lumen/shadow` (routes and other files nothing imports) and `.lumen/types`
  (route types);
- `types` containing `"lumen/env"` (Lumen's globals).

## Example

```json
{
  "compilerOptions": { "strict": true, "jsx": "react-jsx" },
  "include": ["src"]
}
```

## How to fix it

Extend the tsconfig that `lumen check` generates, which holds all of these options and pairs
linked packages too (decision-25), and add your own options on top:

```json
{
  "extends": "./.lumen/tsconfig.generated.json",
  "compilerOptions": { "strict": true }
}
```

Or set the option named in the message, as its help line says.
