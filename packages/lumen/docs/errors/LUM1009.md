# LUM1009: Content nested too deeply

**Severity:** error · **Category:** file format (1xxx)

<!-- end of generated header -->

> A Markdown or HTML import nests elements or block quotes deeper than 512 levels.

**Reported by:** the Vite plugin (`lumen({ md, html })`), in `lumen dev` and builds, at the first
element or line past the limit.

## What it means

The HTML tree builder and the Markdown block parser get slower with every level of nesting, and
a file with tens of thousands of unclosed `<div>`s or `>` markers would take seconds to compile
(or stall the dev server on every save). No real document nests this deep, so Lumen checks the
depth before parsing and stops at 512 levels: elements that are opened and never closed, or block
quote markers on one line. Elements whose end tag is optional (`<p>`, `<li>`, `<td>`…), void
elements and self-closing tags do not count. The component is empty until the file is fixed.

## Example

```html
<!-- generated markup that never closes its wrappers -->
<div>
  <div>
    <div>
      <div><div>…</div></div>
    </div>
  </div>
</div>
```

## How to fix it

Close the elements you open, or generate flatter markup. For a quote of a quote of a quote, a few
levels are plenty.
