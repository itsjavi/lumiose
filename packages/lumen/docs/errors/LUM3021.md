# LUM3021: Unsafe `$` constant value

**Severity:** error · **Category:** styles (3xxx)

<!-- end of generated header -->

> A `$` constant used in a style block holds text that could end its declaration, its rule or the `<style>` element.

**Reported by:** the CSS compiler (`lumen_css`), in `lumen/vite`, `lumen check` and the language server. An error; the constant is not inserted.

## What it means

`$name` inserts the constant's value as CSS text into one declaration value. A value with `{`, `}`
or `;` outside a string, a `/*` comment, an unterminated string or a trailing `\` would end the
declaration or the rule and add CSS of its own, outside the component's scope; a `<` anywhere
(even in a string) could end the `<style>` element in the page's HTML. When the value comes from
data, that is an injection; even from the project, it silently breaks the scoping. So such a value
is refused.

## Example

```stsx
const accent = "red; } body { display: none";

export function Badge() {
  return (
    <span class="badge">
      New
      <style>
        .badge { color: $accent; }
      </style>
    </span>
  );
}
```

## How to fix it

Keep each constant to one CSS value (`"red"`, `"1px solid #000"`, `"\"Inter\", sans-serif"`). For
several declarations, use several constants, or set a custom property from a `style` prop and read
it with `var()`.
