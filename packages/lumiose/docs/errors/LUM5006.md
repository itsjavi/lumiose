# LUM5006: Prerendered page that renders only in the browser

**Severity:** error · **Category:** routing and server (5xxx)

<!-- end of generated header -->

> An `spa` page sets `export const prerender = true`, but its `ssr` is `false`.

**Reported by:** the route scanner (`lumiose dev`, `lumiose check`, `lumiose build`).

## What it means

The two options ask for opposite things. `prerender = true` renders the page's HTML at build time,
and the browser hydrates it. `ssr = false` renders the page only in the browser: the server sends
an empty shell and never loads the page's modules. The `ssr = false` can come from the page itself,
from a layout above it, or from the project default `lumiose({ ssr: false })`.

## Example

```stsx
// src/routes/_layout.stsx
export const mode = "spa";
export const ssr = false;
```

```stsx
// src/routes/index.stsx
export const prerender = true;
export default function Home() {
  return <h1>Home</h1>;
}
```

## How to fix it

- **To prerender the page,** let it render on the server: remove `export const ssr = false`, or
  set `export const ssr = true` on the page. Then move browser-only code (`window`, `document`,
  `AudioContext`, `localStorage`) out of module scope and component setup, into event handlers or
  `onMount()`.
- **To keep the client-rendered shell,** remove `export const prerender = true`. A shell without
  params is already written to a static file by `lumiose build`.

`lumiose({ prerender: true })` together with `lumiose({ ssr: false })` is rejected by the plugin
for the same reason. With only `lumiose({ prerender: true })`, a page that sets `ssr = false`
stays a shell without this error.
