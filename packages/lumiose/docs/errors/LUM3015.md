# LUM3015: Invalid CSS ignored

**Severity:** warning · **Category:** styles (3xxx)

<!-- end of generated header -->

> Lightning CSS dropped an invalid rule, declaration or selector from a `<style>` block.

**Reported by:** the CSS compiler (`lumiose_css`), in `@lumiose/vite`, `lumiose check` and the language server. A warning.

## What it means

Like browsers, Lightning CSS skips what it cannot parse and keeps the rest: for example a rule
whose selector uses an unknown pseudo-class, or a malformed at-rule. The output works, but without
the dropped part, which is usually a typo.

An unknown at-rule is kept as written and reported too, except Tailwind CSS v4's (`@apply`,
`@reference`, `@theme`, `@utility`, `@variant`, `@custom-variant`, `@slot`, `@source`, `@plugin`
and `@config`), which Tailwind's Vite plugin processes after Lumiose (see
[Styles](../concepts/styles.md)).

## Example

```stsx
<style>
  .card { padding: 1rem; }
  .card:hoverr { color: blue; }
</style>
```

## How to fix it

Fix or remove the reported rule or selector (`.card:hover`). If it targets a newer browser feature on
purpose, check the configured browser targets.
