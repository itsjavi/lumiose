# LUM1010: Source nested too deeply

**Severity:** error · **Category:** file format (1xxx)

<!-- end of generated header -->

> Brackets in a `.stsx`/`.tsx` file are nested more than 1000 levels deep, or more than 10 nested brackets each follow a `<` that nothing closes, so the compiler refuses the file.

**Reported by:** the compiler, in `@lumiose/vite`, `lumiose check` and the language server. An error.

## What it means

Parentheses, brackets, braces and template substitutions (`${…}`) are counted while the file is
read; strings and comments do not count. Past 1000 open levels the file is not compiled: the
compiler's passes recurse once per level, and a file nested tens of thousands of levels deep would
exhaust the stack of the process that compiles it (the dev server, the language server). Real code
stays far below the limit; generated code (a serialized tree, a minified data blob) may not.

The second limit bounds the parse time. In TypeScript a `<` may open type arguments, so the parser
tries that reading and, when it fails, parses the same text again as a comparison. When a bracket
opened after such a `<` holds the next one, each level doubles the time, and a few dozen levels
would hang the process that compiles the file. So the compiler counts the brackets open at once
that were opened after a `<` with no `>`, `;`, `=`, `&&` or `||` between them (`=>` does not count
as one), and refuses the file past 10. Deeply nested inline types
(`Wrap<{ a: Wrap<{ b: Wrap<{ … }> }> }>`) count the same way, and are the usual cause in real code.

## Example

```ts
// Generated: 5000 nested arrays.
export const tree = [[[[[[/* … */]]]]]];
```

```ts
// More than 10 comparisons, each against a parenthesized assignment that holds the next.
const d = a < (n = a < (n = a < (n = /* … */ 0)));
```

## How to fix it

Split the expression into named parts, or load deeply nested data as JSON (`import data from
"./tree.json"`, or `fetch`) instead of writing it as code.

For the `<` limit, name the inner types with type aliases, or the inner expressions with constants.
