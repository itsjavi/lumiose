# Internationalization

> Built-in locale routing: one set of route files served under each locale's prefix, with locale-aware links, `hreflang` and canonical URLs.

## Concept

### One route file, every locale

List the locales in the config, and declare the ones each page has. The default locale has no
prefix. There is no `[locale]` folder.

```ts file=vite.config.ts
import lumiose from "@lumiose/vite";

export default {
  plugins: [
    lumiose({
      i18n: {
        locales: ["en", "es", "fr"],
        defaultLocale: "en",
      },
      site: "https://example.com",
    }),
  ],
};
```

```stsx file=routes/about/page.stsx
import { locale } from "lumiose";

export const locales = ["en", "es"];

export default function About() {
  return <h1>{locale() === "es" ? "Hola" : "Hello"}</h1>;
}
```

```text
/about      Hello
/es/about   Hola
/fr/about   404: the page does not declare "fr"
```

### Links and the language switcher

`href()` builds URLs in the current locale. `alternates()` lists the current page in each locale
it declares. `locales = "all"` in a layout covers every page below it.

```stsx file=routes/layout.stsx
import { alternates, href, type LayoutProps } from "lumiose";

export const locales = "all";

const names = { en: "English", es: "Español", fr: "Français" };

export default function Layout(props: LayoutProps<"/">) {
  return (
    <div>
      <nav>
        <a href={href("/about")}>About</a>
        {alternates().map((alternate) => (
          <a href={alternate.href}>{names[alternate.locale]}</a>
        ))}
      </nav>
      {props.children}
    </div>
  );
}
```

> **Messages:** Lumiose does not translate or format messages. Use a library keyed by `locale()`:
> the [i18n guide](../guides/i18n.md) shows Paraglide JS and i18next.

> **Details:** missing translations, `<html lang>`, `hreflang` and canonical links, `site`,
> prerendering, detection, SPA routes and the status:
> [Locale routing in detail](../reference/router.md#locale-routing-in-detail).

## API

| API                                                                | Use                                                                |
| ------------------------------------------------------------------ | ------------------------------------------------------------------ |
| `lumiose({ i18n: { locales, defaultLocale, missing?, detect? } })` | Configure locale routing ([reference](../reference/vite.md)).      |
| `lumiose({ site })`                                                | The site's URL, for the absolute URLs of prerendered pages.        |
| `export const locales = [...] \| "all"`                            | The locales a page, endpoint or layout (and everything below) has. |
| `export async function locales({ params })`                        | The locales of a content-driven page, per params.                  |
| `locale()`, `ctx.locale`                                           | The request's locale (server).                                     |
| `locale()` from `lumiose/router`                                   | The current locale, reactive in SPA routes.                        |
| `href(pattern, { ...params, locale })`                             | A URL in the current locale, or in `locale`.                       |
| `alternates()`                                                     | `[{ locale, href }]`: the current page in each declared locale.    |
| `alternates(pattern, params?)`                                     | The same for another route, from its `locales` list.               |
| `Locale`                                                           | The configured locales (typegen).                                  |

## Example

A post exists in the languages it was translated into: a `locales` function decides per params.
`detect` sends a first visit to the visitor's language.

```ts
// vite.config.ts
import lumiose from "@lumiose/vite";

export default {
  plugins: [
    lumiose({
      i18n: {
        locales: ["en", "es"],
        defaultLocale: "en",
        detect: { cookie: "locale", acceptLanguage: true },
      },
      site: "https://example.com",
    }),
  ],
};
```

```stsx file=routes/blog/[slug]/page.stsx
import { href, locale, notFound, type PageProps } from "lumiose";
import { getPost } from "../../../lib/posts.ts";

type Params = { params: { slug: string } };

export async function locales({ params }: Params) {
  return (await getPost(params.slug))?.translations ?? [];
}

export default async function Post(
  props: PageProps<"/blog/[slug]">,
) {
  const slug = props.params.slug;
  const post = (await getPost(slug, locale())) ?? notFound();
  return (
    <article>
      <h1>{post.title}</h1>
      <a href={href("/blog")}>{post.back}</a>
    </article>
  );
}
```

## Common mistakes

Each in full: [Locale routing in detail](../reference/router.md#locale-routing-in-detail).

- **A `[locale]` folder.** The router handles the prefix; a param named `locale` is `LUM5007`.
- **Expecting every page in every locale.** Without `locales`, a page has only the default one.
- **`href()` to a page that is not translated.** Pick a locale from `alternates("/about")`.
- **Hard-coded prefixes.** `"/es" + path` breaks; use `href(pattern, { locale })`.
- **A switcher that does not update the detection cookie.** `/` sends the visitor back.
- **Detection on a prerendered `/`.** A static file never redirects.
- **No `site` for a prerendered site.** `hreflang` and canonical URLs stay root-relative.

## Related diagnostics

- [LUM5007](../errors/LUM5007.md): route param named `locale`.
- [LUM5002](../errors/LUM5002.md): an invalid `locales` export, or a locale the config does not
  list.
