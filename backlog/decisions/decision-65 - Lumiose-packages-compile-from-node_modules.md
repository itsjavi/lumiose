## Context

@lumiose/vite skipped every package in node_modules. An npm-installed @lumiose/ui (or any component library written for Lumiose) was not compiled: its `.tsx` and `.stsx` components, `?client` scripts (decision-63) and islands went unprocessed. Only workspace-linked installs worked (TASK-390).

## Decision

User approval on 2026-10-15 of Photon's TASK-390 proposal:

- **Packages ship their sources, and @lumiose/vite compiles them.** Compiled output was rejected because it depends on the target (server or browser) and on the app's options (CSP mode, dev tools). It would also tie a package to one `lumiose` version and make dev and build diverge.
- **A Lumiose package is any dependency that lists `lumiose` in a dependency field.** No opt-in package.json field is needed. Lumiose's own tooling (the CLI, adapters, editor plugins) is skipped by name. For these packages @lumiose/vite:
  - compiles them;
  - scans them whole, `dist/` included;
  - bundles them with the server code;
  - keeps them out of Vite's dependency pre-bundling, so they share the app's `lumiose`.
- **The `exclude` option's default** becomes "node_modules, except the Lumiose packages installed there". An explicit `exclude` replaces the whole rule.
- The docs call them "Lumiose packages" (`reference/vite.md#lumiose-packages`).

## Consequences

- An app can install @lumiose/ui from npm; the pack smoke test checks it in dev and build.
- Follow-ups:
  - TASK-397: compiler warnings from installed packages;
  - TASK-398: type-checking their `.stsx` files;
  - TASK-399: their CommonJS dependencies.
